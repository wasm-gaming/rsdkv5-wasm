# The gamepad never reaches the engine: SDL_Init(SDL_INIT_EVERYTHING) quits the joystick

**Status: Plan — awaiting approval before any code changes.**

Copy of rsdkv4-wasm's record of the same name; same issue and plan here (rsdkv3, rsdkv4, rsdkv5) (`RECORD/2026-11-20.gamepad-lost-at-sdl-init.WIP.md`
in each). The menu combo half of the report is engine-specs'
(`RECORD/2026-11-20.menu-combo-start-first.WIP.md` there).

## 2026-11-20 11:15 UTC — Report and diagnosis

Report from the owner (play.germade.dev, Sonic 1; DualSense + GuliKit X, Chrome, both
`mapping: "standard"`, no rebinding): the gamepad does nothing in game; Escape opens the pause
menu but Select + Start does not.

Measured in headless Chromium against the live site (play.germade.dev, engines rsdkv4 0.4.1,
rsdkv3 0.3.1, rsdkv5 0.3.1), the owner's data packs (test-roms release, scratchpad only) and a
fake standard pad injected through `Navigator.prototype.getGamepads`:

- Who calls `navigator.getGamepads()` in game, over 2 s: the launcher's `createInput()` (120) and
  the app's fullscreen toggle (120). **The engine glue never does** — in Sonic 1, Sonic CD and
  Sonic Mania. Sonic 3 A.I.R., for comparison, polls every frame (121).
- Emscripten's SDL2 registers `gamepadconnected` / `gamepaddisconnected` and then **removes them**
  during boot. Stack of the removal (rsdkv4, wasm names):

  ```
  EMSCRIPTEN_JoystickQuit < SDL_JoystickQuit < SDL_QuitSubSystem < SDL_InitSubSystem < SDL_Init
    < main                                 (1st: build.sh's main(), SDL_Init(SDL_INIT_EVERYTHING))
    < InitRenderDevice < RetroEngine::Init (2nd: upstream's own SDL_Init)
  ```

  That is `SDL_InitSubSystem`'s `quit_and_error` path: a subsystem after JOYSTICK /
  GAMECONTROLLER in `SDL_INIT_EVERYTHING` (haptic or sensor, not built in Emscripten's port)
  fails, and SDL quits every subsystem it had started in that call — the joystick included. Video
  and events survive because they were already up, or are started again elsewhere.
- So `SDL_NumJoysticks()` stays 0: `ProcessInput()`'s scan (`controllerInit`) never opens a pad,
  `SDL_JoystickUpdate` never samples, and a pad connected later is never heard (the event handler
  is gone — verified: no call into the glue's gamepad handler after a late connect).
- The keyboard works because it is read through `SDL_GetKeyboardState`, unaffected.
- rsdkv3 shows the same two removals (main + engine init); rsdkv5 one, from its boot path.

## Plan

In `scripts/build.sh` (rsdkv4; same in rsdkv3; rsdkv5 wherever its SDL_Init is):

1. Never ask SDL for subsystems the Emscripten port does not have. Replace every
   `SDL_INIT_EVERYTHING` in the patched tree — the `main()` this script writes and upstream's
   `InitRenderDevice()` — with
   `SDL_INIT_TIMER | SDL_INIT_VIDEO | SDL_INIT_EVENTS | SDL_INIT_JOYSTICK | SDL_INIT_GAMECONTROLLER`
   (audio keeps its explicit `SDL_InitSubSystem(SDL_INIT_AUDIO)` from the existing patch). A
   `grep -c SDL_INIT_EVERYTHING` after patching must give 0, so an upstream bump that adds one
   fails the build instead of losing the pad again.
2. Belt and braces, after the engine's init: `SDL_InitSubSystem(SDL_INIT_GAMECONTROLLER)` (it is
   reference-counted, a no-op when already up) — only if step 1 alone does not verify.

No SDK, app or contract change. The SDK's `getGamepads()` wrapper (remapping) is unaffected.

## Verification

- `make build-wasm` (Docker emsdk image), then the same Chromium probe with the site's
  `/engines/rsdkv4/*` routed to the local `dist/rsdkv4/`: no `gamepad*` listener removed by
  `SDL_InitSubSystem`; the glue samples the pads every frame in game; a fake pad pressing right
  moves Sonic (screenshots before / after); a pad connected after boot is picked up.
- `make test`.
- Same for rsdkv3 (Sonic CD) and rsdkv5 (Sonic Mania).
- Release as a patch per engine; play.germade picks the versions up.

## 2026-11-20 11:40 UTC — Implementation (approved), verification blocked on the build

- rsdkv4 / rsdkv3 `scripts/build.sh`: the `main()` the script writes calls
  `SDL_Init(SDL_INIT_TIMER | SDL_INIT_VIDEO | SDL_INIT_EVENTS | SDL_INIT_JOYSTICK | SDL_INIT_GAMECONTROLLER)`;
  a step before the build replaces every remaining `SDL_INIT_EVERYTHING` in the engine source
  (upstream's `InitRenderDevice()`) and fails the build if one is left (the check reads source
  files only: the `.bak` copies earlier `sed -i.bak` steps leave behind matched at first).
- rsdkv5 `scripts/build.sh`: the culprit there is upstream `SDL2InputDevice.cpp`,
  `SDL_InitSubSystem(SDL_INIT_JOYSTICK | SDL_INIT_GAMECONTROLLER | SDL_INIT_HAPTIC)` — haptic is
  what Emscripten's SDL2 lacks, which also names the failing subsystem for v3/v4. A step before
  configuring drops `| SDL_INIT_HAPTIC` (and would replace any `SDL_INIT_EVERYTHING`), and fails
  the build if either is left.
- Local builds (Docker emsdk, session proxy and CA passed to the container): all three patches
  apply and the checks pass; compilation then stops on Emscripten's ports download (zlib, SDL2…
  from GitHub archives), which this environment's egress policy refuses with 403. Not worked
  around; the wasm is not verified yet.
- Other engines reviewed (BlastEm, Snes9x, mGBA, FBNeo, Sonic 3 A.I.R.): their engines read the
  pad every frame; only RSDK v3/v4/v5 lose it (table in engine-specs'
  `RECORD/2026-11-20.menu-combo-start-first.WIP.md`).

Suggested commit (once verified): `fix(build): keep SDL's joystick up — the gamepad works in game`
